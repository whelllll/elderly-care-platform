# 4. 物理结构设计

## 4.1 存储组织

- 数据库：Microsoft SQL Server 2022，架构 `dbo`。
- 三张表均以 `INT IDENTITY(1,1)` 主键建立 **聚集索引**，不建堆表。
- 数据文件放在 `PRIMARY` 文件组；课程设计规模不分区。
- 字符字段统一 `NVARCHAR`，时间 `DATETIME2(0)`，布尔 `BIT`。

## 4.2 索引设计

| 索引 | 表 | 键列 | INCLUDE / 筛选 | 用途 |
|---|---|---|---|---|
| `UQ_monitor_device_sn_bind` | `monitor_device` | `device_sn, bind_time` | 唯一约束自动索引 | 防止同一设备同一时刻重复绑定 |
| `UQ_monitor_device_sn_active` | `monitor_device` | `device_sn` | `WHERE unbind_time IS NULL` | 同一设备最多一条未解绑记录 |
| `IX_M4_device_elder_status` | `monitor_device` | `elder_id, device_status` | INCLUDE `device_sn, device_type, bind_time, unbind_time` | 按老人/状态查设备 |
| `IX_M4_vital_elder_time` | `vital_sign` | `elder_id, collect_time` | INCLUDE `indicator_type, indicator_value, is_abnormal` | 老人近期体征 |
| `IX_M4_vital_abnormal` | `vital_sign` | `collect_time, elder_id` | `WHERE is_abnormal = 1` | 异常体征复核 |
| `IX_vital_device_time` | `vital_sign` | `device_id, collect_time` | — | 按设备查上报明细 |
| `IX_M4_event_elder_status` | `emergency_event` | `elder_id, event_status, happen_time` | INCLUDE `event_level, responder_id, response_deadline` | 老人事件历史/未闭环 |
| `IX_event_status_deadline` | `emergency_event` | `event_status, response_deadline` | INCLUDE `elder_id, event_level` | 超时未响应扫描 |

## 4.3 填充因子与压缩

- 索引填充因子建议 90，兼顾查询与写入；`vital_sign` 写入频繁时可降到 80。
- `vital_sign` 数据量最大，数据稳定后可启用 **页压缩**；`emergency_event` 可启用行压缩。
- 筛选索引只覆盖小比例子集，不额外压缩。

## 4.4 增长与归档

- `vital_sign` 按设备上报频率增长最快；建议按 `collect_time` 月份做归档/分区评估。
- `emergency_event` 记录量较小，保留全量；`monitor_device` 历史绑定行长期保留。
- 课程设计阶段不建分区表；数据量上来后再按 `collect_time` 做月度归档。

## 4.5 权限与并发

- 应用账号只授予 `SELECT/INSERT/UPDATE`，不授予 `DROP/ALTER`。
- 报表/只读角色只访问视图，不直接查基表。
- 事件登记、闭环在存储过程中执行；建议开启 `READ_COMMITTED_SNAPSHOT` 减少读写阻塞（可选）。
