# 1. 局部 E-R 图

![M4 健康监测与应急响应局部 E-R 图](../assets/m4-er.png)

## 1.1 实体与属性

| 实体 | 图中属性 | 说明 |
|---|---|---|
| 监测设备 | 设备编号、设备序列号、设备类型、设备状态、安装位置、绑定时间、解绑时间 | `device_id` 为绑定记录主键，`device_sn` 标识物理设备 |
| 老人档案 | 档案编号 | 成员1 的外部实体，M4 只引用 |
| 体征数据 | 数据编号、采集时间、指标类型、指标值、是否异常、数据来源 | 一行一指标；`device_id`、`elder_id` 通过联系表达 |
| 应急事件 | 事件编号、事件状态、事件等级、触发来源、发生时间、到场时间、响应人、处置结果、响应截止时间、闭环时间 | `elder_id` 通过“涉及”联系表达 |

## 1.2 联系

| 联系 | 基数 | 说明 |
|---|---|---|
| 绑定 | 监测设备 N : 1 老人档案 | 一次绑定区间对应一位老人；同一设备可有多行历史 |
| 产生 | 监测设备 1 : N 体征数据 | 一条体征数据由一条设备绑定记录产生 |
| 拥有 | 老人档案 1 : N 体征数据 | 采集时归属；设备改绑后历史归属不变 |
| 涉及 | 老人档案 1 : N 应急事件 | 事件涉及老人；触发来源是事件属性 |

## 1.3 说明

- `created_at`、`updated_at` 是审计字段，E-R 图未展开。
- 老人档案是成员1 的表，M4 只保留外键，不重复建表。
- “触发来源”是 `emergency_event` 的属性，不单独画“体征数据—触发—应急事件”的直接联系，因为表中没有 `vital_id` 外键。
- “响应人”也是属性，引用 `sys_user.user_id`；图里没有展开账号实体。
