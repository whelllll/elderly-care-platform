# 8. 测试数据

三张表各 20 条，共 60 条。完整 SQL 见 [`04_test_data.sql`](04_test_data.sql)。

## 8.1 前置条件

1. 成员1：`elder_profile` 有至少 20 条 `archive_status = N'正常'` 的老人；
2. 成员4：`09_sys_user.sql`、`10_sys_user_test_data.sql` 已执行；
3. 成员4：`12_sys_user_business_accounts.sql` 已执行，至少有 2 个 `caregiver_%` 账号；
4. 成员4：`01_schema.sql` 已建 `monitor_device`、`vital_sign`、`emergency_event`。

`10` 不再写死 `user_id` 1–5，按 `username` 判重；`04` 也不再写死老人、设备、响应人 ID。

## 8.2 关联方式

| 数据 | 关联方式 |
|---|---|
| 老人 | `elder_profile` 按 `id_card_no` 取前 20 条，使用实际 `elder_id` |
| 设备 | `device_sn` 以 `M4TEST-` 开头，`device_id` 由 IDENTITY 生成 |
| 体征 | 按 `device_sn` 回查实际 `device_id` / `elder_id` |
| 响应人 | 按 `username` 取 `comm_admin`、`org_mgr`、`caregiver_%`，不固定 `user_id` |

街道监管、民政监管只读，不作为 M4 响应人。

## 8.3 重复执行与失败回滚

- 如果已存在 `M4TEST-` 设备，脚本打印提示并跳过，不重复插入。
- 整个插入包在 `BEGIN TRANSACTION` / `TRY...CATCH` 中，任一步失败全部回滚。
- 如果老人不足 20 条、响应人不足 4 个，脚本直接 `THROW`，不会留下半套数据。

## 8.5 验证

```sql
SELECT 'monitor_device' AS table_name, COUNT(*) AS row_count
FROM dbo.monitor_device
WHERE device_sn LIKE N'M4TEST-%'
UNION ALL
SELECT 'vital_sign', COUNT(*)
FROM dbo.vital_sign AS v
JOIN dbo.monitor_device AS d ON d.device_id = v.device_id
WHERE d.device_sn LIKE N'M4TEST-%'
UNION ALL
SELECT 'emergency_event', COUNT(*)
FROM dbo.emergency_event;

SELECT event_status, COUNT(*) AS row_count
FROM dbo.emergency_event
GROUP BY event_status
ORDER BY event_status;
```

同一 `device_sn` 未解绑记录重复数应为 0。
