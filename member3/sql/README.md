# 成员3 SQL实现初版

设计基线：成员3数据字典v4、逻辑结构与范式分析v3，以及成员2数据字典最终版v1。四张表共32字段，不含公共机构表，也不包含审计时间字段。

## 文件及顺序

1. 在SSMS明确选择专用用户数据库，执行 `01_M3_CreateTables.sql`。可独立创建护工6字段、资质9字段、排班6字段、工时11字段，以及内部声明式约束。机构、项目、派单编号列先保留，跨模块参照完整性此时尚未建立，不能视为完整业务部署。
2. 执行 `03_M3_Indexes.sql`，建立四个既定非聚集索引。包含列、键顺序及审核通过筛选条件与最终字典一致。
3. 可先执行 `04_M3_SchemaValidation.sql`，默认只要求内部外键，外部缺失显示“待整合（非通过）”。
4. 成员1创建公共 `dbo.service_org`，成员2创建实际 `dbo.service_item`、订单及 `dbo.dispatch_record` 后，执行 `02_M3_CrossModuleFK.sql`，添加成员3三条出向外键。成员2同时落实其派单到护工、班次的两条反向外键；代码样例在02末尾注释中，默认不会执行。
5. 将04的 `@RequireCrossModuleFK` 改为1，再验证全部八条关联（三条内部、三条出向、两条成员2反向）。成员2可能使用不同外键名称，验证按关联字段及目标检查，不强制其采用成员3命名。

01、02、03为一次性部署脚本，遇到已有对象会报错；不要反复执行，也不要通过删库、删表、禁用约束或跳过外键来解决。每个脚本使用独立事务，失败整体回滚。未提供旧库自动迁移；已有organization_name数据须与成员1核实机构映射后另行迁移，不能随意分配org_id。

## 当前声明式约束

- 4个INT IDENTITY(1,1)主键；所有外键为INT、不自增，删除和更新均NO ACTION。
- 资质两列唯一键 `UNIQUE(caregiver_id, certificate_no)`，同一护工同一证书只允许一行及一个服务项目；工时 `dispatch_id NOT NULL UNIQUE`。
- 五个状态字段严格采用字典枚举及默认值：在岗、有效、开放、待校验、待审核。
- 13条CHECK涵盖五组枚举、证书日期、排班起止和正容量、签退先后、未签退不允许签退位置、认可分钟上限、审核通过必填条件及已知异常通过的非空白说明。
- 可空条件显式判断NULL；分钟比较以BIGINT乘60与DATEDIFF_BIG秒差比较，避免分钟边界计数和INT溢出。需要SQL Server 2016或更高版本。
- 围栏非通过或任一定位为NULL时，审核通过需要说明。位置字符串的格式、范围、距离、异常识别及说明是否充分，留给后续业务实现；本阶段未用CHECK冒充完整围栏核验。

| 责任方 | 前置条件或操作 |

## 待实现的业务约束

本次未编写过程、触发器、视图、复杂查询或测试数据。以下规则尚不由本阶段DDL完整保证：

- 同一护工未取消班次不重叠，允许首尾相接；有派单的班次变更及容量下调须受控。
- 派单时在岗、项目上架、对应服务资质及预约开始日期有效；社区匹配、班次开放、服务区间完整覆盖、班次护工一致。
- 有效服务时间冲突、班次容量及并发控制，与成员2派单写入共享同一事务。
- 工时班次必须等于派单班次；仅已接单有效派单可签到；重复签到更新原记录；服务状态由成员2协调。
- 定位解析、围栏计算、异常人工审核与审核权限；保存异常原结果的历史约束，不能通过更新把异常伪装为通过。
- 只统计审核通过且有效分钟明确的工时，按签到月份归属，跨月不拆分。
